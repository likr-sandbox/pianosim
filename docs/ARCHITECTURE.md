# ピアノ物理モデリング音源 アーキテクチャ設計仕様 (`ARCHITECTURE.md`)

## 1. 設計基本方針と開発制約

本ドキュメントは、ゼロベースで再設計する純Rustモノレポ構成のリアルタイムピアノ物理モデリング音源のアーキテクチャを定義する。

1. **完全クリーンルーム＆ゼロベース再設計**
   - 既存のv1 TypeScript実装（DWG音源・UI・E2Eテスト）には一切依存せず、M1にてリポジトリ構造とWebフロントエンドを白紙から再構築する。
   - 商用知財の自由実施領域（FTO）を確保するため、AGPL-3.0ライセンス実装（OpenPiano等）のコード参照・流用を禁止し、採用する外部クレートは `MIT` / `Apache-2.0` / `BSD` 等のパーミッシブライセンスに限定する。
2. **純Rustモノレポ自己完結（オフライン生成含む）**
   - Cargo workspaceによるマルチクレート構成を採用する。Python/JAXによる実機録音からの逆問題同定はスコープ外とし、全88鍵・230本の弦／ハンマー物理定数および響板・木製リム・空気室・鋳鉄フレームの空間放射特性は、**Rust製のオフライン物理シミュレーションクレート（`piano-body-gen`）**から手続き生成する。
3. **Web / ネイティブ共通のゼロアロケーション・コア**
   - コアDSPクレート群は初期化（`Engine::init(sample_rate)`）以降のオーディオコールバック内で**ヒープ確保ゼロ・ロック取得ゼロ・システムコールゼロ**を厳守する。
   - サンプル正確（sample-accurate）なイベント分割とMIDI 2.0高分解能（16ビットベロシティ・連続ペダル開度 `0.0..=1.0`）を標準入力境界とし、将来のDAWプラグイン（VST3 / CLAP等）およびネイティブ単体再生（`cpal`）へ直結可能なAPIを提供する。当面の実動作ターゲットは **Webアプリケーション** および開発・音響検証・ベンチマーク用の **ネイティブCLI（`piano-cli`）** とする。
4. **Webリアルタイム実行モデル（プロファイル切替なし・常時フル駆動）**
   - GitHub Pages等の静的ホスティングでも `COOP/COEP` ヘッダなしでそのまま動作する **単一スレッド `AudioWorkletGlobalScope` + `wasm32-unknown-unknown`（`+simd128` / `f32x4`）** を採用する。
   - ハイエンドPCをターゲットとし、品質ティア切替や休止弦のスリープ間引きは行わず、**全88鍵・230本・約2.6万モードを毎サンプル常時SIMD駆動**する。
5. **1ファイル500行上限ルール**
   - 全ソースコード（`.rs`, `.ts`, `.js`, `.css`）および設計文書において **1ファイル最大500行以下**（設計目標150〜350行）を絶対規約とし、CI上の検査コマンド（`piano-cli check-lines`）で機械的に検証する。
6. **フォールバック余地と開発ガバナンス**
   - 今回見送った代替要件（プロファイル切替・休止弦スリープ・Wasmマルチスレッド・Python/JAX逆問題同定・8本自由仮想マイク・ノート別Voicing等）の切り替え条件と設計上の事前仕込み（`preset_codec` の生成源非依存分離、`NoteVoicingOffset[88]` ゼロ初期化拡張枠、4モード `F32x4` 境界および弦単位整列の `modal_soa` 配置）は [DECISIONS_AND_FALLBACKS.md](file:///home/likr/pianosim/docs/DECISIONS_AND_FALLBACKS.md) に定義する。
   - Swarm開発規約は [SWARM_WORKFLOW.md](file:///home/likr/pianosim/docs/SWARM_WORKFLOW.md)、継続的に蓄積される実践知見と不変条件は [AGENTS.md](file:///home/likr/pianosim/.agents/AGENTS.md) を参照する。

## 2. 既存物理モデル音源の3大聴覚課題への構造的アプローチ

既存の純粋物理モデリング音源に対して熟練演奏者・エンジニアから指摘される3つの聴覚的課題を、信号処理上の後付けエフェクトではなく物理構造の統合によって解消する。

| 既存モデルの課題 | 物理的発生要因 | 本設計での構造的解決策 |
|---|---|---|
| **1. 強打アタック初期の高域チャープ遊離感** | 単純ウェーブガイドや独立励振モデルでは、打撃パルスと響板・ボディの立ち上がりが時間・位相的に分離（「detached」）して聞こえる | 幾何学的非線形による**縦波プリカーサー**（横波の5〜12倍の速度でブリッジへ先行到達）を弦のブリッジ傾斜角結合へ注入し、さらにStage 4の**ゼロ追加遅延マルチゾーン分割畳み込み**でボディ初期反射と単一時間軸上に統合（「glued together」）する |
| **2. 中高音域の高速連打時のプラスチック的均一感** | メモリレスな打弦モデルおよび全鍵均一の理想境界により、トリルや連打（ribattuto）の揺らぎと有機的個性が失われる | **Stulovヒステリシス緩和フィルタ**の内部状態を離鍵・再打弦間も保持し羊毛フェルトの圧縮記憶効果を再現する。加えてオフライン生成時に鍵・弦ごとの決定論的な微細ブリッジインピーダンス／デチューニング偏差を付与する |
| **3. 長時間演奏時の線の細さ・胴鳴り（身体性）不足** | 2次元平板響板のみの近似では、木製リム・内部空気室・鋳鉄フレームの低中域質量感や棚板の打鍵衝撃が欠落する | **直交異方性リブ付き響板＋木製リム＋3次元空気キャビティ＋鋳鉄フレーム＋大屋根反射**の連成構造モードをオフラインRustソルバで解き、強打時の**鍵盤棚板衝撃（keybed thump）**を構造体放射ゾーンへ直接力インパルスとして入力する |

## 3. 全体2層アーキテクチャ構成

本音源は「第1層：純Rustオフライン物理生成・初期化時IR合成」と「第2層：4ステージ・マルチレート決定論的リアルタイムDSPエンジン」の2層で構成される。

```
[第1層A: ビルド時オフライン生成 (crates/piano-body-gen)]
  88鍵弦スケーリング則 + 異方性響板/リブ/リム/空気室/鉄骨FEM・固有値ソルバ
  ──▶ 縮約ブリッジモード(5〜12極) + 極除去済み放射構造モード群(数百KBバイナリ)
                                │
[第1層B: 初期化・空間変更時 (crates/piano-radiator::ir_synth)]
  実AudioContextレート(44.1/48/96kHz) + 聴取視点 + 大屋根開度
  ──▶ 9ゾーン×ステレオ(18経路) 0.5秒IR動的合成(数十ms)
                                │
                                ▼
[第2層: リアルタイムDSPコア (Zero Heap Alloc / No Locks)]
  MIDI 1.0/2.0イベント(サンプル正確・16bitベロシティ・連続ペダル)
   ├──▶ Stage 1 (piano-action): 接触中のみ8倍(384kHz) Timoshenkoシャンク + Stulov + K-method/ADAA + 片側ダンパー
   ├──▶ Stage 2 (piano-strings): ホスト駆動(48kHz) 230本2偏波+縦自由(~2.6万モード) ZOH + ドリフト制御SAV + ファントム倍音
   ├──▶ Stage 3 (piano-bridge): 5〜12モード縮約ブリッジ双方向連成 + Hertz剛性 + デュープレックス弦 + 3ペダル創発
   └──▶ Stage 4 (piano-radiator): 8ブリッジゾーン+1棚板ゾーン 64tap直接SIMD FIR(遅延0) + NUPOLS FFT畳み込み ─▶ Stereo Out
```

## 4. 第1層：純Rustオフライン物理データ生成と適応IR合成

### 4.1 ビルド時構造音響ソルバと弦スケーリング（`piano-body-gen`, `piano-spec`）
1. **弦設計スケーリング則（88鍵・230本）**:
   - 標準フルコンサートグランド構成（低音単弦8鍵＋複弦18鍵＋中高音トリコード62鍵＝計230本）に対し、弦長 $L(k)$、線密度 $\mu(k)$、張力 $T_0(k)$、曲げ剛性 $ESK^2(k)$ を定義し、インハーモニシティ係数 $B(k) = \frac{\pi^2 E S K^2}{T_0 L^2}$ （A0付近の約 $0.00036$ からC8付近の約 $0.045$ へ連続推移）を解析的に算出する。
   - 各部分音周波数は $f_j = j F_0 \sqrt{1 + B j^2}$ で評価し、Rigaud / Renault らの漸近則に基づく自動Railsbackストレッチ調律と、鍵・ユニゾン弦ごとの決定論的微細偏差（シード固定疑似乱数による有機的ばらつき）を付与する。
2. **複合ボディ構造の固有値解析**:
   - 直交異方性（木目方向剛性・肋木および駒による局所不均質性・ダウンベアリング静荷重を含む）Reissner-Mindlin／Kirchhoff-Love 2次元厚板方程式を、木製リムの弾性支持境界、3次元空気キャビティ音響モード、および鋳鉄フレームの高域補強剛性と連成させて離散固有値問題を解き、1,000〜2,000個の高次構造音響モード（極・空間留数データ、合計数百KB）を抽出する。
3. **縮約ブリッジ分離と二重共振の回避（極除去）**:
   - Miranda Valienteら（JASA 2024）の知見に基づき、ブリッジ駆動点モビリティから弦減衰・エネルギー還流を支配する低域主要モード **5〜12個** をStage 3の双方向結合用「縮約ブリッジアドミタンス」として抽出する。
   - Stage 4の空間放射モデル用の構造モード留数からは、この抽出済み5〜12極の寄与を逆フィルタリング（極除去：pole cancellation）で差し引いて同梱する。これにより、Stage 3（双方向結合）とStage 4（単方向畳み込み）を直列接続した際の二重共振ピークを完全に防止する。

### 4.2 初期化時サンプルレート適応IR合成（`piano-radiator::ir_synth`）
- Web Audioの `AudioContext.sampleRate`（44.1 / 48 / 96 kHz等の任意実レート）、ユーザー選択の**聴取視点プリセット**（`Player`, `CloseStereo`, `ConcertHall`, `BinauralHRTF`）、および**大屋根開度**（`Open`, `Half`, `Closed` および連続補間）に応じて、同梱の極・留数データからその場で **8ブリッジゾーン＋1棚板ゾーン（計9ゾーン×L/R＝18経路、0.5秒相当＝48 kHz時24,000タップ）** のIR波形を数十msで動的合成する。
- これにより、大規模な事前レンダリングWAV群（数十MB）を配信することなく、Pianoteq並みの極小バンドル容量とホストサンプルレートへの厳密追従を両立する。

## 5. 第2層：4ステージ・リアルタイムDSPパイプライン

### 5.1 Stage 1：非線形打弦・シャンク・片側接触ダンパー系（`crates/piano-action`）
- **局所8倍マルチレート更新（384 kHz＠48 kHz基準）**: ハンマーと弦の接触は打鍵後約1.0〜4.5 msで完了するため、接触中（$\Delta y = y_h - y_s > 0$）にあるアクティブなノートのみをホストの8倍サンプルレートで局所実行する。
- **1次Timoshenko柔軟シャンク**: レットオフ後の自由飛行および打弦反力によるシャンクの回転運動と曲げ振動を1次状態方程式で解き、打弦アタックの立ち上がり形状に反映させる。
- **Stulovヒステリシス羊毛フェルト接触**:
  $$F(t) = k \left[1 - h_r(t)\right] * (\Delta y(t))^p, \qquad h_r(t) = \frac{\epsilon}{\tau_0} e^{-t/\tau_0} \quad (\Delta y(t) > 0)$$
  ここで指数 $p \in [2.2, 3.5]$ はフェルト非線形性を表し、畳み込み核 $h_r(t)$ は1次IIR緩和フィルタとして実装する。緩和フィルタの状態変数を離鍵後も保持し続けることで、振動中の弦への再打弦・高速連打時にフェルト圧縮履歴が反映される。
- **K-method & ルックアップテーブルADAA**: 非線形接触力 $F[n]$ と圧縮変位 $\Delta y[n]$ の遅延なしループは、BorinらのK-method（$\Delta y[n] = p[n] + K F[n]$ の陰的関係式の事前解・テーブルルックアップ）で解消する。さらに接触非平滑性に起因する折り返し歪みは、ルックアップテーブル型ADAA（Antiderivative Antialiasing）および0.5サンプル群遅延に対するフィードバック位相整合補償によって抑制する。
- **片側ヒステリシス接触ダンパー**: 鍵のリリース変位、連続サステインペダル開度、およびソステヌート保持状態から算出される幾何学的クリアランスを境界入力とする片側接触要素として定義する。これによりハーフペダルおよびリペダリング時の高次倍音選択減衰を物理的に創発させる。

### 5.2 Stage 2：全弦2偏波モード＋ドリフト制御SAV非線形弦バンク（`crates/piano-strings`）
- **SoA（Structure of Arrays）メモリ配置とキャッシュ常駐**:
  - 230本×垂直・水平2偏波の20 kHz以下全可聴横モード（約23,514モード）および低〜中音域の縦自由モード（約1,670モード）の計 **約25,200〜26,200モード** を、64バイト境界整列（`#[repr(align(64))]`）された連続平面配列として保持する。
  - 各モードの状態変数 $(q_m[k], q_m[k-1])$ と係数 $(a_{1,m}, a_{2,m}, b_m, c_{\text{vert},m}, c_{\text{horiz},m})$ を64B整列SoAに収めることで、総作業メモリを約490 KB（L2キャッシュ内）に抑え、分岐なしFMA演算で一括更新する。
- **ZOH（ゼロ次ホールド）／インパルス不変2次モード更新式**:
  $$q_m[k+1] = 2 r_m \cos(\Omega_m T_s)\, q_m[k] - r_m^2\, q_m[k-1] + b_m f[k]$$
  周波数プリワーピング不要でナイキスト周波数まで数値的ピッチ分散誤差を完全にゼロに保つ。
- **パワーバランス保存型ドリフト制御SAV法（DAFx 2025）**:
  強打時の横振動大振幅に伴う張力変調ポテンシャル $E_{nl}(q) \ge 0$ に対し、ゲージ定数 $C_0 > 0$ と単一のスカラー補助変数 $r(t) = \sqrt{2 E_{nl}(q) + C_0}$ を導入する。Risse, Hélie & Bilbao（DAFx 2025）に基づき、補助変数ドリフト誤差 $\epsilon(q, r)$ に対するパワーバランス保存型摂動制御項 $g_{\text{mod}}$ を結合則へ組み込むことで、非線形反復ソルバーなしで1ステップ陽的更新による無条件受動性と、100回連続強打下でもゼロに近いピッチドリフト抑制を両立する。
- **縦波プリカーサーとファントム・パーシャル**:
  ブリッジにおける弦の微小なダウンベアリング傾斜角を通じた横・縦連成により、高速伝播する縦波プリカーサーをブリッジ力へ先行出力する。さらにBank & Sujbert（2004, 2005）の強制応答定式化に基づき、横振動の非線形二乗駆動項 $\partial_x[(\partial_x u)^2]$ から偶数次ファントム・パーシャル（$2f_m$）および奇数次ファントム・パーシャル（$f_n \pm f_m,\; |n-m|=1$）を横・縦統合系として直接生成する。

### 5.3 Stage 3：縮約モード双方向ブリッジ連成＆3ペダル機構（`crates/piano-bridge`）
- Stage 2の全230本の弦終端（およびデュープレックス・スケール弦の共鳴モード）を、Hertz接触剛性 $k_c$ と第1層で同定した5〜12モードの縮約響板アドミタンス状態空間へ**分岐なしで一様に双方向結合**する。
- **自然創発するピアノ固有現象**:
  1. **二段階減衰（Two-stage decay）とうなり**: 響板垂直偏波（大ブリッジ結合・急速減衰）と水平偏波・微小デチューニングされた逆位相ユニゾン弦（小結合・緩減衰）の相互作用により、アタックの鋭い立ち上がりと長い余韻が自動生成される。
  2. **シンパセティック共鳴**: サステインペダル踏込時、および無音でゆっくり押鍵（サイレントキー）した他弦への倍音共鳴が、共通ブリッジ力のみを介して条件判定ゼロで発生する。
  3. **ウナ・コルダ（左ペダル）**: 連続左ペダル値に応じてハンマー打撃軸が横シフトし、トリコード3本のうち2本（複弦は1本）のみを打撃する。打たれなかった残余弦はブリッジ経由でエネルギーを吸収・再放出し、柔らかい音色と特有の二段階減衰を生む。
  4. **ソステヌート（中央ペダル）**: 踏み込み瞬間にダンパーが開放状態にあった鍵のクリアランスのみを機械ラッチで保持する。

### 5.4 Stage 4：ゼロ追加遅延マルチゾーン分割畳み込み放射＆ボイシング（`crates/piano-radiator`）
- **空間射影と棚板衝撃ゾーン**: ブリッジを音域・位置に沿った8ゾーンへ分割し、各弦の位置重みで駆動力を射影する。さらに鍵盤の底突き衝撃力（高音域強打ほど顕著なkeybed thump）を第9ゾーン（棚板構造入力）へ力インパルスとして注入する。
- **非一様分割FFT畳み込み（NUPOLS）**:
  - 0.5秒IR（24,000タップ＠48 kHz）の先頭64サンプルを**直接SIMD FIR**で処理して**追加アルゴリズム遅延ゼロ**を保証する。
  - 64サンプル以降のテールはブロックサイズを段階拡大（例: 64 → 128 → 256 → 512 → 1024 → 2048）した非一様分割畳み込み（FDL: Frequency-Domain Delay Line）により18経路（9ゾーン×L/R）を低負荷で計算する。
- **リアルタイム・ボイシング再計算**: ハンマー硬度（$K, p$）、ユニゾン揺らぎ量、ストレッチ調律度、弦長スケール変更時は、解析的分散式およびStulovパラメータ式を直接再評価し、クロスフェードまたはパラメータ平滑化を通じて安全に反映する。

## 6. SIMD抽象化・Web Wasm実行・ネイティブ境界

### 6.1 ポータブルSIMD抽象化（`crates/piano-simd`）
- 共通4レーンSIMD型 `F32x4` を定義し、コンパイルターゲット別にネイティブ組み込み命令へゼロコスト写像する。
  - `target_arch = "wasm32"`（`+simd128`）: `core::arch::wasm32::v128`（`f32x4_add`, `f32x4_mul` 等）
  - `target_arch = "x86_64"`（AVX2 / FMA有効時）: 8レーンラッパーまたは `SSE/AVX`
  - `target_arch = "aarch64"`: `core::arch::aarch64::float32x4_t`（NEON）
  - 上記以外のフォールバック: `[f32; 4]` スカラ実装（同一テスト結果のビット近似検証用）

### 6.2 Web AudioWorklet + Wasm IPC（`crates/piano-wasm`, `apps/web/src/audio`）
- **スレッド分離**: メインスレッド（Vanilla TypeScript UI / Web MIDI / SMFプレイヤー）は、AudioWorkletの `port.postMessage` または共有メッセージキュー経由でサンプルオフセット付きコマンドを送信する。`AudioWorkletProcessor::process()`（128サンプル／量子）内部では、Wasmインスタンスの線形メモリ上に事前確保された固定長コマンドキューからイベントを取り出し、`PianoEngine::process(events, out_l, out_r)` を単一スレッド同期実行する。
- **テレメトリ計測**: 1量子ごとの処理経過時間（`performance.now()`／モノトニック計測）およびブリッジ・ピークレベルを間引きリングバッファでメインスレッドへ返し、UI上でp50/p99処理時間とスペクトルを可視化する。
- **Rust→Wasmビルド規約**: `.cargo/config.toml` に `rustflags = ["-C", "target-feature=+simd128"]` を明記し、生成Wasmバイナリが確実にSIMD128命令を含むことをCIで検査する。

### 6.3 ネイティブ拡張境界（`crates/piano-engine`, `crates/piano-cli`）
- `PianoEngine` はプラットフォーム非依存（`no_std` 互換コアまたは `std` は初期化時のみ使用）とし、`render_block(&mut self, events: &[SampleEvent], out_l: &mut [f32], out_r: &mut [f32])` の単一エントリポイントを提供する。
- `SampleEvent` は `sample_offset: u32`, `channel_key: u8`, `velocity_q16: u16`（MIDI 2.0 16ビット正規化）, `pedal_kind / value_q16` を保持し、将来のVST3/CLAPラッパーや `cpal` オーディオコールバックから直接呼び出せる。
